## 1. 要解决的问题与边界

agentview 中的物体互相遮挡，可能使 SAM3 无检测、mask 不完整，或使 grasp pose estimate / advisor 无法给出可用抓取。恢复能力必须能在产生 `compiled_grasp_id` 之前启动，而不仅服务于已有抓取候选的精修。

- 保留 agentview 为固定的语义基准相机，不增加移动 agentview 的能力。首次明确目标时保存原始观察与关系消歧依据；腕部移动后不能按新图像的前后/左右重新解释原任务指代。
- 感知工具给出质量证据和建议，Agent 决定是否移动、选哪个视角、何时停止或继续。Host 不强制扫描次数、工具顺序或任务阶段。
- Host 负责证据来源、几何计算、有效期和安全 gate；提供候选不等于批准执行，运动到达不等于目标更清晰或任务取得进展。
- 身份连续性不代表冻结错误判断。原先消歧不确定时保留不确定性；确有错误时须显式修正并保留来源，不能以禁止重新解释为由永久锁错目标。
- 主动观察不承诺能恢复完全不可见的物体，也不包含自动挪开遮挡物；若需要后者，属于另一类操作及安全评估。

## 3. 用户提出的候选方案 A：扩展现有视点工具

以下是设计草案，不是当前可直接执行的 API 示例，也不预先承诺字段名称。

1. 保留 `propose_wrist_viewpoints` 的 `compiled_grasp_id` 分支，评估新增 `identity_anchor_id` 分支，不新增重复的 `move_camera`。若采用双分支，须规定互斥或一致性规则，不能让相互矛盾的目标引用静默覆盖。
2. Host 从原始目标证据、深度与标定恢复目标空间位置，结合当前腕部标定/机器人状态生成视点。原 agentview 证据与当前 wrist 标定是不同来源，不能合并成含糊的一个 `source_packet_id`。
3. Host 采样不同方位角、俯仰角和距离，做工作域初筛与几何去重，提供有界集合。4–8 个是可评估的默认范围，不是要求凑满的最低数量；零个或更少时报告原因，候选数量不由 Agent 任意填写。
4. Agent 自选一个候选，通过现有 `ik_preview_check(viewpoint_proposal_id, candidate_id)` 取得适用的 receipt，再调用 `move_to(ik_receipt_id)`；精确碰撞检查及 HV-01 的控制器执行限制仍适用。
5. 获取实际运动后的 wrist observation，提供候选 `target_projection_handoff`：实际 `source_packet_id`、wrist camera ID、预测点或 ROI、原 `identity_anchor_id`。额外需要考虑投影状态、不确定范围、标定/几何版本、运动 receipt 与候选来源。
6. Agent 参考投影调用 SAM3，检查新检测与原目标的一致性，再经现有 selection 接口提交 `same_instance`。未确认时允许拒绝、保持歧义或继续观察，不自动绑定 ROI 内最接近的检测。

候选排序信息可包括：目标预计是否在视野内、与当前视角的角度差、预计像素尺度、深度覆盖/遮挡质量估计、是否仍需精确 IK 和碰撞检查。必须区分测量值、模型估计与 unknown；单视角无法判断被遮挡表面时，不应返回虚假的确定可见性。这些字段都不是安全授权。

可能触发建议的证据包括：SAM3 无检测或 mask 截断、mask 太小或深度不足、多个候选难以消歧、grasp advisor 因遮挡 abstain、`compute_wrist_alignment` 返回 `requires_better_view`。它们是 Agent 可参考的理由，不是强制转移条件；首次无检测的场景还取决于下一节的启动设计。

## 4. 落地前必须回答的问题

### 4.1 首次 SAM3 就失败：锚点从何而来？

方案 A 能直接覆盖“已有确认 mask，但没有可用抓取候选”的情况。若首次 SAM3 无检测，当前 selection 路径无法创建身份锚点；再要求“原始 mask + identity_anchor_id”会保留原来的循环依赖。

需要比较的选项，而非本轮定案：

- 扩展身份锚点的来源，允许固定 agentview 上已确认的 point/ROI/其他 grounding 证据，显式区分临时定位与已确认实例。改动较集中，但会改变所有锚点消费者原有的证据假设，不能只添加一个可选字段。
- 身份锚点保持现有语义，另以宿主定位证据引用承载尚未完成分割的空间区域，获得可靠分割后再显式关联/升级身份。证据层次更清楚，但增加一种资源及解析规则；这不意味着必须新增一个运动工具。
- 当没有可信目标深度时，由 Host 提供经安全约束的场景级观察位候选，只为收集更多信息，不宣称以目标中心为准。可作为更弱的退路，但它不能保证目标可见或已经确定“那一个物体”。

建议先用有 mask 无 grasp、无 mask 有可见点/ROI、无可信深度三类小用例比较这些选项，再决定工具输入。分阶段实现可以从方案 A 开始，但不能把该阶段宣称为完整的分割前遮挡恢复。

### 4.2 身份、三维定位与空间关系应分开

身份锚点回答“是哪一个”，定位证据回答“此时在哪里”，固定语义参照回答“为什么最初选它”。三者生命周期不同：机器人移动不应换身份；物体移动会使旧世界坐标过期；原始任务消歧证据可作为历史保留。

从局部 mask 恢复的点可能只是可见表面，不是物体中心；point/ROI 的深度还可能来自遮挡物。需要深度覆盖、有效像素与不确定范围检查，不能用 ROI 中心的一个深度值冒充可靠目标位置。参考帧、深度单位、内外参方向和标定版本应有明确来源。

跨视角投影只提供搜索区域。同类物体重叠、相机误差、遮挡或物体位移都可能使投影落在另一个物体上。应保留原图对照、匹配证据与冲突状态；`same_instance` 不能自动升级为宿主验证结论。HV-04 的把手定位还应关联原物体，不能把部件 ROI 当作整物体身份或携带包络。

### 4.3 谁负责生成绑定新 packet 的投影？

用户建议由 motion receipt 直接返回 handoff；这是可评估的包装方式，不宜先锁定所有权。现有 handoff 只指向下一 planner context 的 packet，因此需先核对观测捕获与注册时序。

- 若新 observation 在运动调用返回前已捕获并注册，可将投影作为该调用的关联证据返回。
- 若实际 packet 在后续 observe/context 构建时才产生，应先返回待解析关联，再由 observation 层绑定真实 packet；不能提前填入不存在的 packet ID，也不能悄悄引用旧图。

无论外部封装在哪层，投影应使用图像采集时的实测相机位姿，而非请求到达的理想位姿。零步、未到达、相机帧缺失、投影出界、目标位置过期均需明确状态。未到达但获得有效新图时，可以提供基于实际位姿的投影，同时保留未到达结论；不得伪报候选已成功执行。

### 4.4 质量排序与运动安全不能混为一谈

工作域初筛、视野预测、遮挡评分只能辅助选候选，不代替关节限位、路径碰撞、机器人/携带物几何和实际控制器检查。未知遮挡或缺少碰撞证据时应如实返回 unknown/限制，不能以评分高作为执行授权。是否可在持物时主动观察也须显式考虑当前 attachment 和携带包络。

Host 可以维护证据有效/过期、请求完成/失败等状态，但不据此强制 Agent 执行预设任务流程。这是“无强制任务状态机”的边界，不是要求系统完全无状态。

## 5. 设计验证与后续待办

- [ ] 首次 SAM3 无检测且无 compiled grasp 时，至少有一条明确、受证据约束的观察恢复入口；无可信定位时如实拒绝或给出场景级候选，不捏造目标锚点。
- [ ] 两个相似黑碗因腕部换位出现图像前后次序反转时，保留原任务参照与身份；投影歧义不会静默换目标，必要时回看固定参照。
- [ ] 杯把手只有侧后方可见时，候选覆盖有效方位；采用 Host 有界集合，不要求 Agent 填数量或执行固定扫描轮数。
- [ ] 覆盖遮挡物深度、无效深度、部分 mask、物体移动、标定变化、相机出界和邻近同类物体；投影带明确不确定性或失效状态。
- [ ] 覆盖零步、实际偏离候选、运动后 packet 尚未注册及重复只读 observe；身份历史不随 robot epoch 丢失，旧运动授权也不会因身份仍有效而被复用。
- [ ] 验证 projection → SAM3 的点/ROI 坐标与互斥规则；selection 仍显式确认身份，部件 selection 与整体身份不混淆。
- [ ] 候选分数、感知失败建议与 `same_instance` 声明均无法跳过现有 IK、碰撞、执行或证据所有权 gate；Agent 可以选择不移动。
- [ ] 保留现有 compiled-grasp 路径回归；设计确认后再同步 schema/resolver/receipt/文档生成与契约测试，并按 HV-03 重测 Spatial 0、Long 9，统计身份错误、有效视角、抓取质量与额外动作成本。

建议决策顺序：先定无分割启动证据与身份生命周期，再定新 packet 投影的生成边界，最后决定是否采用方案 A 的公开参数与默认采样策略。本轮不新增运行时接口、不移动相机、不把记录提案视为修复完成。

## 6. 2026-09-06 实现候选与待决策项

现有 compiled-grasp 分支已实现 [有界多方位采样](wrist-viewpoint-sampling.md)：四方位、40°/65° 两俯仰，共八个独立候选，保留相机安装变换。新增几何角度差和明确 unknown 的可见性/遮挡信息，不做自动扫描或安全授权。当前没有工作域初筛，也没有取得“杯把手重新可见”的真实证据，因此不勾选第 5 节的实验验收。

另修复 proposal ID 未覆盖旋转/完整候选几何的问题，并改用既有短 ID 路径作为推荐 IK handoff。仅刷新 packet 而几何相同仍可得到相同 ID；这不代替所有后续 freshness 检查。输入仍须 compiled grasp，没有新增 identity-anchor 分支或 projection handoff。

已向用户提出无分割启动的设计选择：**建议将 point/ROI 弱定位作为独立 Host 证据，可靠分割后显式关联 identity_anchor**，不把弱定位直接当作已确认实例。另一选项是扩展 anchor 并审计全部消费者的临时/已确认语义。当前尚未收到确认，未据此创建新资源或修改 anchor 语义。

本次只读核对共享 RFC revision 2158 的契约评审规则；第 1 段网络限制属于 2026-09-05 的历史核查情况。新增输出字段、候选上限、hash 和 handoff 提示仍为个人分支候选，待三人评审；未写共享文档。

后续有效期审计已补充：成功结果、严格 epoch、来源/标定绑定、活动目标与最新同相机 mount 复核，以及嵌套位姿的独立拷贝。等价新 packet 和同身份新 mask 不会仅因 ID 刷新而被判过期；缺少来源的旧精简记录需要重新生成。详见 [采样与引用有效期](wrist-viewpoint-sampling.md)。这些检查仍未创建分割前入口或绑定新图的目标投影，也不证明远端 operation 已退出。
