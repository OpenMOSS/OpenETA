# Codex Mink：约束运动过程的 Cartesian segment 跟踪

用户授权在 Codex plugin 分支优化底层控制器，不仅优化最终 pose 误差，也要减少运动过程发散。本次修改位于 `OpenETA-codex-plugin` 的 `dev/huaizezheng/codex-plugin-smoke-2026-09-08`，未修改 main 工作目录，未提交或推送。

## 最终行为

每个 move_to 仍由 agent 提供目标，先运行原有 IK preview。新控制器沿起点至终点的直线平移，并在起终姿态间按最短角度插值；追踪的参考点最多领先当前进度 15 mm 或 2°。平移和转动同时存在时，由较慢的进度限制参考前进，避免先到 XYZ 再大幅转腕。

一次 QP 速度只有通过以下条件才执行：

- 非线性 FK 预测的平移步长不超过 8 mm，转角不超过 4°。
- 预测位置距请求线段不超过 8 mm，姿态偏离相应插值姿态不超过 4°。若实际反馈略超这个预测余量，允许明确向该范围收敛的候选，禁止继续偏离。
- 原有机械臂、夹爪、携带物和关节安全检查全部保留。已发生硬越界时仍需验证单调退出；原有 QP fallback 的边界退出规则继续生效。
- 完整速度不满足时，最多检查 6 个比例：1、1/2、1/4、1/8、1/16、1/32；均失败就返回，不关闭碰撞检查或生成其他任务路径。

执行后独立检查实际位姿：距请求线段超过 10 mm 或偏离插值姿态超过 6°时停止。预测与实际的差额为 PID/接触动力学留出余量。这是控制 tick 级检查与停止规则，不是对连续时间内绝无瞬时越界的保证。

连续 25 个控制步间隔内，位置误差改善不足 0.5 mm、角度误差改善不足 0.5°时，返回明确停滞原因。纯旋转有角度进展就不会被误判成“位置不动”。原有最终位置、角度、稳定到达条件和最大步数不放宽。

路径不通时，agent 应在净空处改变姿态或提供新的途径点。控制器不会因终点存在 IK 解就直接插值到 seed 的关节角，也不会使用官方任务 region 或私有物体语义替 agent 规划。

## 实现范围

- `sim/controllers/cartesian_segment.py`：几何参考、过程偏离度量、有限缩步和无进展检测；只使用请求/测量的机器人 pose。
- `sim/controllers/mink_goal.py`：跟踪中间参考、逐候选检查、实际状态检查、控制回执。普通进程默认不启用，需 Host 环境变量 `OPENETA_LIBERO_CARTESIAN_SEGMENT=1`。
- `scripts/codex_sim_server.py`：Codex 专用 Mink 启动器默认启用。`--no-cartesian-segment` 用于配对基线；OSC 不启用。该开关不是 agent 的 tool 参数。
- `tools/codex_feedback.py`：明确反馈 `cartesian_segment_blocked`、`cartesian_path_deviation`、`cartesian_progress_stalled`，保留已执行步数和机器人路径指标。
- `tools/codex_atomic.py`：在 move_to 描述中说明默认路径行为、终点可达不等于路径可执行。

没有修改接触授权范围、碰撞阈值、夹持证明、官方成功判定、模型、AnyPlace 等工具。本次未调整抽屉接触授权，仍作为独立待办。

## 回放方法

用上一轮实验已保存的 move-start 状态，在独立的兼容 LIBERO 环境中恢复后，分别执行原冻结控制器和新控制器。目标、IK seed、接触授权、夹爪指令、动力学状态、最终容差和步数上限保持相同。每个控制步记录实际 grip-site 轨迹及原受保护几何的距离。回放不调用模型，也不计入任务 pass@2。

先完成 9 组接近、搬运和受阻样本，再加入 4 组原先成功的大角度旋转。早期版本的角度参考过远、权重过高以及预测余量过紧，确实造成正常旋转退化；这些版本的结果以 iteration 文件保留。最终版将角度参考限制在 2°，并恢复更平衡的位置/角度权重，四个旋转全部通过，再以最终参数重跑九组核心样本。下表只使用最终版。

Long 5 搬运书时，相对直线进度所对应插值姿态的峰值角偏差从 **55.83° 降到 1.86°**；Spatial 0 从 **46.92° 降到 0.54°**。这里是过程跟踪误差，不是最终目标角误差。

新控制器到达的动作仍满足原位置每轴 2 mm 和原角度容差；最终位置误差不是每条都更小，例如 Object 1 接近的范数误差从 0.57 mm 变为 1.39 mm，仍在原容差内。优化重点是减少过程绕行，同时保持到达条件。部分动作控制步数增加。

所有独立环境已关闭。13 组新控制器的控制 tick 测量中，受保护几何间距没有低于原 -1 mm 硬阈值。不能把这一有限样本结论外推成所有场景的绝对安全保证。

## 反馈与契约

现有顶层 stop_reason 继续使用 `control_step_failed` 或 `local_convergence_stalled`，通过 controller_failure.code 区分新的原因。可见路径指标仅包含机器人自身轨迹偏离和缩步次数，不包含障碍名字、碰撞 geom、私有 region、最优途径点或仿真成功距离。

例如：

```json
{
  "reason_code": "control_step_failed",
  "physics_executed": true,
  "motion_summary": {
    "controller_failure": {"code": "cartesian_segment_blocked"},
    "path_tracking": {
      "enabled": true,
      "path_peak_cross_track_m": 0.00797,
      "path_peak_rotation_deviation_rad": 0.0091,
      "path_backtracked_steps": 10
    }
  }
}
```

该示例用于说明字段，不是某次完整回执。新增原因和反馈字段属于兼容性增加，**合入 main 前仍需按协作约定进行三人契约评审**。本地隔离分支实现与验证已获用户授权，无外部发布。
