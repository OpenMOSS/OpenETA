## 1. 确定的姿态转换错误

`agent/tools/sim_mcp.py::_extract_orientation_arguments` 的 quaternion 分支，
在 pitch=90° 奇异位置分别计算 roll/yaw 时遇到 `atan2(0, 0)`，丢失耦合旋转。

独立使用 SciPy 重建旋转，最小复现：

```text
输入 quat_xyzw = [0.5, 0.5, -0.5, 0.5]
解析得到 roll/pitch/yaw = [0, 90, 0] deg
重建 quat_xyzw = [0, 0.70710678, 0, 0.70710678]
两旋转相差 90°；接近轴从世界 -Y 变成 +X。
```

按动作顺序对应全部 22 次实际 move 的 worker 快照，并逐项断言目标位置一致后，
比较 atomic feedback 选中姿态与 worker 收到的四元数：只有 native #7、#20 存在偏差，均为 90°；
其他 20 次偏差低于 0.001°。

| 请求 | 选中姿态 | worker 接近轴 | 结果 |
| --- | --- | --- | --- |
| #7 | 上述四元数，接近轴 -Y | +X | control_step_failed；114 步；对 worker 目标残差 23.40° |
| #20 | 上述四元数，接近轴 -Y | +X | local_convergence_stalled；95 步；对 worker 目标残差 13.16° |

`move_to` 和 `ik_preview_check` 共用这个转换函数，因此 preview 和执行可以对错误目标保持一致。
“IK seed 验证通过、receipt 匹配”不能证明 agent 原始目标被完整保留。
候选旋转成本按原姿态计算，而 IK 指标来自转换后的姿态，也会削弱候选比较的含义。
只读 AST 比较确认 main 的同名解析函数与本分支一致；main 未修改。

优先修正姿态转换，并加入 agent 目标 → IK → worker 的旋转一致性检查；
覆盖 pitch=±90°、邻近奇异点、q 与 -q、180° 等价候选。
检查应比较旋转矩阵或旋转距离，而非欧拉角数值是否相同。

## 2. 三次拉动实际没有有效带动抽屉

从保存的模型和 integration state 恢复配置，调用 `mj_forward`，不执行物理步。
下表接触是配置重建结果，不是原运行逐步接触力历史。

| 闭合 / 拉动请求 | 闭合后横杆接触 | 两指垫距横杆 | 实际末端 +Y 位移 | 抽屉打开增量 |
| --- | --- | --- | ---: | ---: |
| #17 / #18 | 两侧 finger_collision；指垫无接触 | 2.005 / 1.660 mm | 78.61 mm | 0.001057 mm |
| #27 / #28 | 仅 finger1_collision；指垫无接触 | 1.406 / 1.355 mm | 61.71 mm | 0.000073 mm |
| #33 / #34 | 仅 finger2_collision；指垫无接触 | 4.565 / 4.205 mm | 89.33 mm | 0.000166 mm |

三个拉动动作始终带 `gripper_command=+1`，排除意外切换打开命令。
拉动后快照中均已没有手指与横杆接触，夹爪趋于闭合。
这支持“未建立可靠夹持、随后接触丢失”；不能仅凭这些边界状态认定摩擦不足或拉动过快。
指体接触本身也不必然不能抓取，需结合实际拉动几乎未传递位移共同判断。

三次闭合之前的接近 #16/#26/#32 均以 150 步 iteration_limit 结束，
位置残差分别为 4.75、4.99、19.04 mm，模型随后仍选择闭合。
尚未完成预期接近就尝试抓取，是模型决策与抓取反馈不足共同需要处理的问题。
现有 gripper feedback 已明确 `attachment_proven=false` 并要求检查；并未虚报抓取成功，
但缺少直接的双侧接触/指垫位置诊断，`gripper_horizon_completed` 只说明命令执行完毕。

最终抽屉 qpos=-0.01221492 m，不代表这些拉动有 12.2 mm 成果：

- #12 撤离时打开增量约 8.16 mm；随后 #16 接近又向关闭方向移动约 10.46 mm。
- 三次闭合拉动产生的增量均小于 0.002 mm。
- #42 最后撤离时 qpos 从 +0.00084731 变成 -0.01221492 m，打开增量约 13.06 mm。

这是动作边界归因，未记录逐步接触力，不能据此指定撤离时是哪一个接触点产生了作用。

## 3. 碰撞限制是其他接近方案失败的因素

#11/#23 授权的是横杆 `wooden_cabinet_1_g18`，预测下一步碰到相邻连接几何 `g20` 被拦截。
应审查把手部件的合理接触范围，避免横杆打点遗漏相邻把手组件。
另两次是手指与柜子其他几何 #38、机械臂 link4 与酒架 #41，需调整全臂路径。
不能通过授权整个柜子解决这些不同类型的碰撞。

四次都是下一步配置预测拒绝，原报告的负距离不是已发生的穿透深度。
现有碰撞检测确实在工作；本次证据更支持修正目标传递、夹持诊断与路径，
而不是先叠加一套重复的碰撞检测。
