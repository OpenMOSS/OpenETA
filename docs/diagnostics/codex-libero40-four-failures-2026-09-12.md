# LIBERO 40：四个 pass@2 失败任务诊断

评测结果保持不变：Astra/high，固定官方初始状态 0，pass@1 = 34/40，pass@2 = 36/40。本文检查 Object 1、Goal 5、Long 3、Long 5 的两次独立会话。没有修改冻结执行源码、benchmark、原始结果或任务成功条件，没有补跑第三次任务。

证据目录：`tmp/codex-libero40-pass2-20260911/`。新增诊断产物：`tmp/codex-libero40-failure-diagnosis-20260912/`。

## 结论

存在值得修改的通用 harness 问题，优先级为：

1. **局部碰撞约束求解与精确步进检查不一致时的处理**：QP 给出的完整步被几何检查否决后，当前直接结束 move_to；缺少受限步长回退、重新求解和明确的局部无进展报告。不能把下一步预测碰撞误解成当前已穿透或所有退路均不可行。
2. **局部执行贴近关节限位，与已验证 IK 解脱节**：Goal 5 多次有充足关节余量的有效终点解，但实际局部执行落到另一姿态分支，卡在 Panda 第 4 关节边界。单纯延长执行步数不能解决这个问题。
3. **活动部件接触授权过于依赖单个 collision geom**：Long 3 推同一抽屉时，授权把手或面板的一个 geom，接触同一刚体上的其他 geom 仍被视为非目标障碍。需要按局部物理接触部件建模，不能整柜放行。
4. **视觉空间理解与失败后的恢复流程**：Long 5 首要错误是把左右侧格误认成后格。通用的多视角辨认、落点复核、低高度释放与脱困流程值得加强，不能用仿真 region 的名字或坐标替 agent 做语义判断。

无需首先增加 AnyPlace/SAM/AnyGrasp 或第三类任务级工具，也没有证据支持直接放宽碰撞阈值、关闭检查或修改官方成功判定。

## Object 1：当前安全，但下一步危险

两次均在 request 8 关闭夹爪后报告 `bilateral_pads`，request 9 请求世界系上抬 6 cm。原始私有碰撞对为 `gripper0_hand_collision` 与 `tomato_sauce_1_g9`。第一轮预测间距 -3.05 mm；第二轮 -2.69 mm；均为 `pre_actuation_configuration`，执行步数为 0。实际关节最小余量约 0.95 rad，姿态误差接近 0，不是 IK 角度不可达或关节限位。

使用第二轮保存的 move-start 状态，在兼容的独立 LIBERO 环境恢复后，调用原始 Mink 求解器，仅截获第一条 QP 速度并在副本上检查。没有执行诊断运动，没有模型调用。三个样本的完整步预测与原记录一致。

| 样本 | 当前最小间距 | 原始完整步预测 | 缩小步长的预测 |
|---|---:|---:|---:|
| Object 1 第二次，首次抬升 | +1.601 mm | -2.693 mm | 1/4 步 +0.439 mm |
| Object 1 第二次，释放后抬升 | +0.745 mm | -2.140 mm | 1/16 步 +0.165 mm |
| Long 3 第二次，最后退让 | +0.0144 mm | -9.642 mm | 1/16 步 +0.0147 mm |

这些小步只证明存在未越过硬碰撞阈值的**局部候选**，不证明能完成整段运动。它们没有全部通过现有的单调边界退出规则；Object 1 缩步仍缩小了间隙，不能作为恢复成功。需要验证“受限步长 + 重求解 + 真正退出接触边界”，不能用循环小步逐渐挤进障碍。

代码证据：`sim/controllers/mink_goal.py` 在 452 行附近构造完整速度步的几何预测，在 652 行附近遇到 `preview["detected"]` 直接 break。QP 使用 Mink 自身的距离/法向，而 worker 的精确检查还合并显式接触距离（1640 行附近）；求解约束与验收几何不是完全相同的信号。当前复算尚未分离距离退化、法向切换和有限步长非线性各自的贡献，不能把其中某一个认定为唯一底层原因。

## Goal 5：有效终点解没有转化成有效局部路径

第二次的 6 次 `iteration_limit` 中，后 4 次实际第 4 关节最小余量接近 0，存在 1e-7 rad 量级越界数值；对应保存的 IK seed 最小关节余量分别约 **0.775、0.525、0.525、0.715 rad**，而执行回执均为 `ik_seed_validated=true`。因此是局部控制停在边界，不能概括成目标 pose 本身无 IK 解；有效终点仍不代表到该点有无碰撞路径。

其中一条转姿态运行了 300 步，仍有 16.57° 误差。其他碰撞也真实涉及不同障碍：柜子、黑碗、奶酪和桌面；不是同一种接触授权可以统一解决。

最后保存状态中，盘子中心位于 `[-0.0056501, 0.1962368, 0.9023181]`，官方目标区域 X 上界为 -0.01，所以横向仍差 **4.35 mm** 才进入该边界，官方失败符合定义。这些目标区域数据仅用于操作者诊断，不作为 agent 反馈或新工具输入。

第二次 atomic 工具累计约 857 秒，整次运行约 2432 秒。剩余时间包含模型往返、输出和其他调度开销，不能全部称为网络故障或推理时间。当前条件 A 默认没有笛卡尔位置无进展窗口；应启用/改进短窗口停滞诊断，再让 agent 改姿态或退到净空处。需要专门的无进展规则；原有其他实验 profile 的规则还包含横向漂移条件，不宜直接切换整个 profile 来混合评测。

## Long 3：两条不同的阻塞链

第一次关闭抽屉时，底层关节从 -0.1460 移到 -0.03748，确有约 10.86 cm 推进。私有回执显示授权 `g40` 后碰 `g41`/`g33`、授权 `g33` 后碰 `g35`。恢复保存模型确认这些 geom 全属于 `white_cabinet_1_cabinet_bottom`，即**同一个活动抽屉刚体**，而不是另一层抽屉或固定柜体。

源码 `sim/libero_contact_geometry.py:56` 校验单个 geom；`sim/controllers/mink_goal.py:1376` 把授权目标集合设为该单元素集合。因此“目标表面已授权，其他都是目标外障碍”的反馈在机械语义上不够准确。

建议把接触授权限制在模型已标记的那个活动部件上的局部接触区域，兼容相邻面片/碰撞分解；保留固定框架、其他抽屉、掌部深穿透和整条手臂的检查。**同一刚体是必要依据之一，但不是任意部位无限接触许可。** 这涉及授权语义，需要单独设计和回归，而非扩大到整柜。

第二次并未进入有效关闭阶段：request 30 开始转姿态时 `robot0_link6_collision` 与酒架碰撞，之后 clearance/retreat 同样失败。上面的第一步复算仅说明小步候选可能存在。该样本还需要净空处先转姿态、机器人整体路径可行性和局部恢复，不能预期仅扩大抽屉接触授权就解决。

## Long 5：后格辨认错误在先，狭窄空间恢复失败在后

两次首次运输终点的 Y 约 -0.28，落在左侧格；第二次后来运输至 Y 约 -0.008，落在右侧格。保存的最终模型状态、原始 camera image 和模型自己在失败前的描述一致。真正的后格是中间后侧的窄格，因此第一因是空间关系识别和放置计划错误。

原始 camera 图片另存为 `book-first-0.png`、`book-last-0.png` 等，未改图；它们来自 agent 当时确实收到的 MCP 图像。后格位置和官方 region 仅用来审计，不应加成“哪个格才正确”的仿真特权提示。已有 observe/crop/mark_point 足以支撑多视角辨认；可加强技能中对容器自身前后与屏幕左右的区分。

后期也有真实执行问题：第二次 request 66 的 5 cm lift 在 150 步后还差 49.5 mm，request 68 要求上提到 1.26 m 后仍差 234.6 mm。关节余量约 0.25 rad、角误差约 0.22°，不是之前的大角度不可达；更符合受接触/避障约束的局部停滞。私有指垫接触检查确认后期双侧接触确实在书上，不能把它解释为夹住盒壁，也不能把双侧接触等同于可顺利提出书。

第一次还出现书与收纳盒 `g8` 的携带物轨迹碰撞；第二次多次是手指与盒壁 `g2` 的碰撞。外层 endpoint AABB 拒绝与内层轨迹/物理接触必须分别分析，目前没有足够证据认定这些 endpoint 拒绝全部为误报。

## 建议改动与验证顺序

1. **先改局部控制诊断及保守恢复。** 区分当前硬越界、下一步被否决、QP 无解、边界内但无法前进。统一 QP 与验收的几何口径，增加有限次数的步长回退/重求解，保持原硬阈值、携带物检查和逐步反馈；无安全进展立即返回明确原因。用 Object 1 和 Long 3 的保存状态做对照回放，并增加真正越界不可放行的负例。
2. **处理有效 IK seed 与局部限位的脱节。** 短窗口判定位置/角度停滞，反馈是哪类约束；研究净空路径和受保护的姿态分支调整。不能直接插值到 seed 关节角，也不能因 seed 有解就忽略碰撞。
3. **修订活动部件的接触授权。** 对抽屉同部件相邻几何建立局部接触范围，配套“同部件邻面/固定结构/其他障碍”的非语义泄露反馈。必须保留禁止整柜豁免的负例，按协作约定做授权/反馈契约评审后再合入 main。
4. **改善一般性技能和反馈。** 容器多视角定位、接近失败后先恢复净空、狭窄格口释放前复核、双侧接触后短距离抬升验真。`tools/codex_feedback.py` 当前还会丢弃部分 attached-object check_mode 和更具体的 controller failure，应使用明确的允许列表补齐原因，而不透传私有几何名、距离、region 或原始错误字符串。

这些建议尚未改入 harness，也没有证明改后四任务都能成功。下一版应先做保存状态的局部回归，再独立测试任务；保留当前 90% pass@2 作为原冻结版本结论。
