结论：掌部被中层抽屉的把手挡住，碰撞 QP 因而抑制继续前进；底层把手接触授权正常。
Host 将这一情况压缩为通用的 `cartesian_progress_stalled`，没有解释活跃的掌部障碍约束。
本次没有修改运行时代码、扩大接触范围或启动新的模型任务。所有分析均在独立 worktree 内完成。

## 排除项与反馈缺口

- 不是终点 IK 无解：两次均有有效 IK receipt，关节余量约 1 rad。
- 没有发现新的 90 度姿态转换错误：请求 29 主动选择 `jaw_world=[0,1,0]`，随后保持该方向。
  实际 grip-site X 轴与夹指滑动轴的绝对点积为 0.999999999999994；符号差来自夹指轴的定义。
  body→grip-site 的既有 -90 度标定也与实际模型一致。
- 不是底层接触目录缺项：四次接触运动均使用 `local_articulated_patch`，其中两次到位、两次停滞。
  中层把手属于另一个 articulated body，正确地保持保护。
- `collision.detected=false` 在这里表示没有触发 1 mm 硬停止阈值，不表示完全没有接触、
  没有 QP 避碰约束或路径可继续。浅接触已足以使 QP 阻止深入。

当前 `mink_goal.py` 在 segment stall 分支只填入 stop code；新的 `candidate_obstacles`
诊断仅覆盖无候选步通过检查的分支。这里 QP 每次都有一个很小的合法速度，所以不会进入该分支。
`gripper_contact=no_contact` 则只描述夹指与外部物体的接触，不覆盖掌部。
这两个信息缺口叠加，使 Agent 看到的是“未检测到碰撞 + 无夹指接触 + 进展停滞”，而看不到
真正的掌部障碍。

## 建议后续改动

1. 在停滞回执中补充窗口内持续活跃、确实限制目标方向进展的约束类别，以及掌部/手臂接触状态。
   复用已有 `base_or_palm`、`outside_contact_target` 等允许公开的类别；不返回几何 ID、
   仿真物体坐标或隐藏目标。不能把任意活跃约束都称为失败原因。
2. 恢复信息区分“未超过硬碰撞阈值”和“被避碰约束限制”。此类情况应先退出接触，再改变腕部姿态
   或接近方向，避免仅降低同一路径目标、增加迭代或继续向内推。
3. 如补充预览，可显示已知机器人自身的掌部轮廓/包络，而不只显示夹指开口线。
   这仍是机器人标定几何，不需要 SAM3、AnyGrasp 或场景特权信息。具体替代姿态的可达性和
   全程安全性仍需另行验证；本次没有证明某条替代路线能够完成任务。

不建议通过放宽其它抽屉的接触授权来解决此问题。任何新增公开反馈字段在合入 main 前仍需三人
接口评审；本次诊断未更改公开接口。
