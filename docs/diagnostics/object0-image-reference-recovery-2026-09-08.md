# Object 0 continuation: exact image evidence references — 2026-09-08

## Scope and implementation (not task acceptance)

Continue the standard Luna Object 0 task after the reference-comparison delivery.
The earlier correct identification was one positive example, not demonstrated
success-rate improvement. No automatic semantic selector or new motion gate is added.

The full attempt exposed an interface defect: planner visual history publishes
`observation:{observation_index}:{frame_id}` and current camera context publishes
`current_observation:{step}:{frame_id}`, but `inspect_evidence(image_ref=...)`
previously accepted only filesystem paths. Therefore the prior diagnostic's
description of observation labels as a caller mistake was incomplete: these IDs
are actually generated by the Host and presented to the planner.

`inspect_evidence` now resolves an **exact registered image evidence ID** in the
current session, or accepts the existing saved-path form. Historical IDs retain
their original image and provenance. A current-observation alias resolves only
for the latest observation. Unknown/ambiguous IDs and files outside the session
artifact root remain rejected. Viewing never refreshes epochs, confirms identity,
or authorizes motion. No guessed frame/step or default-image fallback is used.

Example: `inspect_evidence(image_ref="observation:0:agentview")`, only when that
exact ID has been published for this session. Existing bundle paging is unchanged.

Shared-interface addition needs collaborator review; viewer remains declared,
approved contract hashes and stable interface profile are unchanged. Shared RFC
access remains unavailable; this is a local implementation/experiment record,
not a shared RFC approval or publication.
